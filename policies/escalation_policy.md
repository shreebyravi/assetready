# Tessmar Facility Services: Escalation Policy (fictional)

Simplified, fictional policy. Cite it by section, for example "Escalation 2.3".

## 1. Who decides

1.1 The **FM handover manager** approves every recommendation, every clarification request and every status change, and signs formal acceptance outside this tool.
1.2 The **FM operations manager** is consulted on life-safety assets before acceptance.
1.3 The **main contractor's project manager** (Halvorn Contracting) receives clarification requests for anything the contractor or subcontractors must fix.

## 2. When to escalate

2.1 A life-safety asset (fire systems, lifts, standby generator) has any open exception.
2.2 An asset match is uncertain (Matching 3.1).
2.3 Evidence conflicts and no source settles it.
2.4 Anyone asks for an asset to be accepted, marked ready or signed off outside the readiness rules, including because of a payment, a deadline or a promise that documents will follow.
2.5 A tool fails or a document cannot be read, so the investigation is incomplete.

## 3. How to escalate

3.1 State the trigger, who should decide, and what they must decide.
3.2 Leave every record unchanged. The asset is not marked ready.
3.3 If you are refusing an out-of-policy request, start the summary with "REFUSED - <section>: <reason>".

## 4. What the tool never does

4.1 Accept or sign off an asset, or set a status of accepted.
4.2 Send a message to a contractor. It drafts; a person approves; sending is simulated in this prototype.
4.3 Change any register or document.
